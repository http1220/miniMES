- 테스트: `SensorValueValidatorTests.cs`

## 1. 무엇을 판정하는가

유효성 판정은 값을 측정 데이터로 받아들일 수 있는지 확인하는 작업이다.
유효하면 true, 유효하지 않으면 false를 반환한다.

이상값(NaN, 무한대, 유효 범위 밖 값, 무효 상태 코드)과 값 이상(알람 임계 초과)은 다르다.
예를 들어 유효 범위가 0~100이고 알람 임계치가 80이면, 90은 유효한 값이면서 알람 대상이다.
상태 코드 2도 설비의 이상 상태를 나타내는 유효한 코드다.

0~100은 학습용 범위이며 실제 설비의 고정 범위가 아니다.
이번 연습에서는 양 끝을 포함하도록 정했다. 실제 범위 경계 정책은 요구사항과 결정 기록에서 확인해야 한다.

## 2. 단위 테스트의 기본 구조

1. 준비: 입력, 허용 범위, 기대 결과를 정한다.
2. 실행: 실제 판정 메서드를 호출한다.
3. 확인: 실제 결과와 기대 결과를 비교한다.

유효하지 않은 입력이라도 예상대로 false를 반환하면 테스트는 통과한다.
101을 넣고 true를 기대했을 때 실패하는 것도 직접 확인했다.
Expected는 기대 결과, Actual은 실제 결과다.

## 3. 자료형과 비교

- 온도·진동은 float32이므로 이번 연습에서는 float를 사용했다.
- 소수 리터럴에 f를 붙여 float로 표현했다.
- NaN은 문자열이 아니라 float가 표현하는 특별한 값이며 매개변수로 전달할 수 있다.
- NaN의 대소 비교는 false다. 현재 범위 비교는 유한한 범위에서 NaN과 양·음의 무한대를 거부한다.
- 상태 코드 uint16은 C#의 ushort에 대응하며 0~65535를 담을 수 있다.
- 자료형에 담을 수 있다는 것과 업무 규칙상 유효하다는 것은 다르다.
- &&는 두 조건 모두 참, ||는 하나 이상 참, ==는 동등 비교다.

## 4. 실제 코드와 테스트 분리

처음에는 테스트 클래스 안에서 판정 메서드를 작성했다.
이후 Core의 SensorValueValidator로 이동하고 테스트 프로젝트에서 호출하도록 바꿨다.
프로젝트 참조와 public 접근 지정자가 필요하며, using Core는 이름을 짧게 쓰도록 돕는다.
using은 구현 코드를 복사하거나 객체를 생성하지 않는다.

객체 방식에서는 지역 변수 또는 필드에 객체를 보관할 수 있다.
xUnit은 테스트마다 테스트 클래스 객체를 새로 만들며 생성자에서 준비 작업을 할 수 있다.
현재 판정은 객체의 필드 없이 매개변수만 사용하므로 static 메서드로 정리했다.
static 메서드는 클래스 이름으로 호출하고 특정 객체를 가리키는 this가 없다.
객체마다 메서드 코드가 복사되는 것은 아니다. 객체마다 달라질 수 있는 것은 필드의 데이터다.
객체별 허용 범위를 보관하는 설계라면 객체 방식이 자연스럽다.
필드를 static으로 만드는 것은 메서드를 static으로 만드는 것과 다르다.

## 5. xUnit과 이름 짓기

- Fact: 개별 테스트를 표시한다.
- Theory와 InlineData: 동일한 검사 구조에 여러 입력과 기대 결과를 전달한다.
- Assert.True / Assert.False: 고정된 bool 기대값을 확인한다.
- Assert.Equal: 기대 결과와 실제 결과를 비교한다.
- 테스트 클래스는 검사 대상 이름에 Tests를 붙여 SensorValueValidatorTests로 정리했다.
- 테스트 메서드는 검사 기능, 입력 상황, 기대 결과를 드러내도록 이름을 정했다.
- 변수 이름은 단순 번호보다 값의 역할을 나타내도록 정했다.

## 6. 현재 실행 사례

| 분류 | 사례 | 수 |
|---|---|---:|
| 범위 Theory | 25.5, -1, 101, 0, 100을 0~100 범위로 판정 | 5 |
| 특별한 float 값 Fact | NaN, 양의 무한대, 음의 무한대 | 3 |
| 서로 다른 범위 Fact | 75를 0~100과 0~50에 각각 적용 | 1 |
| 상태 코드 Theory | 0, 1, 2는 유효, 3과 65535는 무효 | 5 |
| 합계 | | 14 |

서로 다른 범위 테스트는 전달된 범위에 따라 결과가 달라지는지를 확인한다.
실제 설비 ID에 맞는 설정을 선택하는 동작까지 검증하지는 않는다.
테스트 수보다 필요한 상황이 유지되는지가 중요하다.
이전 테스트들은 주석으로 남아 있지만 실행 사례에는 포함되지 않는다.
