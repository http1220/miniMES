# 0010. 인증 범위

- 상태: 채택
- 날짜: 2026-09-30

## 맥락

- 사람 사용자: 작업자·보전 담당자·관리자가 알람 확인과 고장 기록을 남긴다
- 시스템 클라이언트: 사내망에 있는 수집기와 화면이 Server에 요청한다. 인증이 없으면 사내망의 아무 PC나 가짜 샘플을 넣거나 알람을 조작할 수 있다

## 결정

- **사용자 인증은 범위 밖**이다. 작업 시 사용자 목록에서 선택하며 비밀번호는 없다. 역할은 문서상 구분이고 앱은 권한을 강제하지 않는다
- **시스템 클라이언트는 종류별 API 키**로 인증한다. 수집기 키와 화면 키를 각 PC의 환경 파일에 두고, Server는 키마다 허용 API를 제한한다(수집기 키: 수집 전송만, 화면 키: 조회·확인·고장 기록만)
- 전송 구간은 HTTPS, DB 연결은 암호화한다. DB 계정은 관리자 계정이 아닌 이 DB 전용 로그인이며 접속 정보는 Server에만 있다

## 검토한 대안

| 대안 | 버린 이유 |
|---|---|
| 사용자 인증 + 역할 권한 | 범위가 크다. 인증 없이 메뉴만 숨기면 다른 사용자 선택으로 우회돼 보안 착시가 생긴다 |
| 클라이언트 인증 없음 | 사내망 위장 위협을 그대로 남긴다 |
| 상호 TLS | 가장 강하지만 인증서 발급·배포·갱신 부담이 크다 → **강화안** |
| Windows 통합 인증 | 도메인 환경이 필요하다 |

## 결과

- 이력의 "누가"는 자기 신고라 부인 방지가 되지 않는다(수용)
- API 키가 유출되면 그 종류의 클라이언트로 위장할 수 있고, 키 교체는 수동이다(수용)
- 단일 DB 계정이 스키마 변경 권한을 가진 위험은 수용하되, 서버 전체가 아닌 이 DB로 범위를 제한했다
