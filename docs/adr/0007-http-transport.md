# 0007. HTTP 통신과 MQTT 전환 조건

- 상태: 채택
- 날짜: 2026-09-30

## 맥락

수집기는 샘플·알람을 보내고 "DB에 저장됨" 응답을 받아야 한다(ADR 0006). 화면은 조회와 기록을 요청한다. 구성 요소는 다른 LAN·VPN에 있을 수 있고 인터넷에는 노출하지 않는다.

## 결정

- **HTTPS + JSON**. Server는 ASP.NET Web API OWIN 셀프 호스팅, 클라이언트는 `HttpClient`
- **연결 유지**: 클라이언트당 `HttpClient` 하나를 재사용해 핸드셰이크는 재연결 때만 발생
- **묶음 전송**: 수집기는 최대 25건씩 묶어 보낸다

## 검토한 대안

| 대안 | 버린 이유 |
|---|---|
| MQTT (수집 경로) | 브로커 ACK는 "DB 저장됨"이 아니라 응답 토픽을 따로 만들어야 하고, 브로커라는 실패 지점이 늘며, .NET Framework용 라이브러리가 지원 종료된 구버전에 묶인다 |
| WCF | 설정이 복잡하고 최신 .NET에서 서버가 공식 지원되지 않는다 |
| TCP 직접 프레임 | 통신 계층을 다시 구현해야 해 실패 시나리오가 크게 는다 |
| gRPC | .NET Framework 서버 지원이 사실상 없다 |
| UDP | 도착 보장을 다시 만들어야 한다 |

대역폭(추정, 미측정): 헤더 크기를 가정하면 묶음 전송 기준 HTTP가 MQTT의 약 2배지만, 수집기 100대여도 1Mbps 미만이다.

## 결과

- **MQTT 전환 조건**: 수집기가 수백 대 이상이거나, 묶기 어려운 작은 메시지가 많거나, 여러 화면에 실시간 push가 필요할 때. 이때 DB 저장 확인은 응답 토픽으로 구현한다
- 핸드셰이크·요청 오버헤드는 테스트 단계에서 측정한다
