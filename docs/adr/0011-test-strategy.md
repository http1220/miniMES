# 0011. 테스트 전략

- 상태: 채택
- 날짜: 2026-09-30

## 맥락

DB는 외부에 따로 구성한 SQL Server다. 공개 레포의 CI에서 외부 DB에 접속하려면 포트 노출과 비밀정보 관리 문제가 생긴다.

## 결정

- **CI(GitHub Actions Windows 러너)는 단위 테스트와 비밀정보 검사만** 실행한다
- 판단 로직(판정, 백오프, 시각 계산, MTBF·MTTR, 상태 전환, 설정 검증)은 Core에 두어 단위 테스트로 검증한다(ADR 0004)
- DB 제약(중복 방지, 활성 알람 유일성, 알람-고장 1:1)과 프로세스 간 동작은 **통합 테스트로 로컬에서** 외부 DB를 대상으로 실행하고, 결과를 PR에 첨부한다
- SQL 단위 테스트 프레임워크(tSQLt)는 쓰지 않는다

## 검토한 대안

- **CI에서 LocalDB·Express 설치**: PR마다 DB 동작을 검증할 수 있지만 러너 환경 확인과 설정이 필요하다
- **CI에서 외부 DB 접속**: 공개 레포에 포트·비밀정보 위험이 생긴다
- **tSQLt**: CI 밖에서만 실행돼 증명력이 약하고 설치가 추가된다

## 결과

- "CI 통과"는 DB 관련 동작을 보장하지 않는다. PR의 로컬 통합 테스트 결과로 보완한다
- 네트워크 장애는 장애 주입 프록시로 재현한다(ADR 0013)
