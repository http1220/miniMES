# 0005. 시각의 단일 원천과 기준점 방식

- 상태: 채택
- 날짜: 2026-09-30

## 맥락

- 수집기·화면·Server·DB가 서로 다른 PC일 수 있어 시계가 여러 개다. 같은 "UTC"라도 PC마다 몇 초씩 어긋날 수 있고, 시간 동기화 순간 점프한다
- 수집기 정지 판정(수 초 단위), MTBF·MTTR(시각 간 차이)은 시계가 섞이면 틀어진다
- DB나 Server가 끊긴 동안에도 수집기는 샘플에 시각을 찍어야 한다

## 결정

- **시각의 진실 원천은 Server 시계 하나**다. 저장 시각은 모두 UTC다
- 수집기·화면은 PC 시계(벽시계)를 쓰지 않는다. Server 시각을 받은 순간의 단조 시계 값과 짝지어 **기준점**으로 두고, 사건 시각 = 기준점 시각 + 단조 시계 경과로 계산한다. 수집기는 heartbeat마다 기준점을 갱신한다
- 기준점이 없으면(시작 시 Server 단절) 샘플에 단조 시계 값만 두고, 기준점을 받으면 거꾸로 계산해 시각을 확정한다
- **시각은 뒤로 가지 않는다**: 설비별로 새로 확정한 시각이 직전 시각보다 이르면 직전 시각으로 고정한다. 기준점이 임계값(기본 1초) 이상 점프하면 로그에 이벤트를 남긴다
- 경과 시간 판정(타임아웃, 백오프, heartbeat 판정)은 각 프로세스의 단조 시계로 한다

## 검토한 대안

| 대안 | 버린 이유 |
|---|---|
| 각 PC의 UTC 시계 | PC 간 오차가 초 단위 판정에 그대로 들어간다 |
| 용도별로 시계 분리 | 판정은 시계 하나로 하지만 원천이 여러 개로 남는다 |
| 모든 PC를 같은 NTP에 동기화 | 동기화 사이 오차가 있고, 앱이 원천을 보장하지 못한다 |
| 저장 시점 시각만 사용 | 단절 중 버퍼에 쌓인 샘플의 수집 시각이 틀어진다 |
| 시계를 서서히 맞추기(slew) | 판정 단위가 초라 과하다 |

원리는 NTP의 축소판이다(원천 하나, 왕복 시간 보정, 기준 상실 시 자체 시계로 이어 세기, 역행 금지).

## 결과

- 기준점 오차는 왕복 시간의 절반 수준으로 예상한다. 측정하지 않았으며 테스트 단계에서 측정한다
- Server 시계가 크게 조정되면 저장 시각도 함께 점프한다(로그로 드러남)
- 큰 역방향 점프 시 그동안의 샘플이 같은 시각에 몰릴 수 있다
