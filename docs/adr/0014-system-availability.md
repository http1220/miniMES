# 0014. 설비 연계: 시스템 구조와 시스템 가용도

- 상태: 채택
- 날짜: 2026-10-03
- 관련: ADR 0001(범위 밖 목록 개정), ADR 0008(공백 계산 재사용)

## 맥락

설비는 실제로 서로 독립되어 있지 않다. 시스템은 여러 설비(부품)로 이뤄지고, 한 설비가 멈추면 시스템이 서는 경우(직렬)와 다른 설비가 버텨 주는 경우(병렬·예비)가 있다. 설비 단위 MTBF·MTTR은 정확하게 만들 수 있어도, 그것만으로는 "시스템이 얼마나 쓸 수 있었나"에 답하지 못한다.

신뢰성 분야에서는 설비 단위 지표를 신뢰성 블록 다이어그램(RBD)으로 조합해 시스템 지표를 구한다. 설비 단위 지표는 그 조합의 입력이다.

## 결정

- 감시·고장 기록·지표의 **기본 단위는 설비**로 유지하고, 그 위에 **시스템 구조**를 둔다
- 구조는 **설비 / 직렬 / 병렬 세 종류 노드의 중첩 트리**다. 깊이 제한이 없고, 재귀 계산 하나로 처리한다. 설비 1대만 있는 시스템(독립 설비)은 이 구조의 특수 경우다
- 구조는 DB의 자기참조 노드 테이블에 둔다. 외래 키·CHECK·고유 인덱스로 막을 수 있는 오류는 DB가 막고, 순환·자식 없는 묶음 노드는 계산 전에 검증한다. 구조 오류가 있으면 **그 시스템만** "산출 불가(구조 오류: 이유)"로 표시하고 다른 기능은 계속 동작한다
- 설비 가용도는 **실적 가용도** = (관측 시간 − 고장 정지 시간) ÷ 관측 시간
  - 관측 시간 = 조회 기간 − 수집 공백(ADR 0008)
  - 고장 정지 시간 = 고장 기록의 알람 발생 ~ 복구 완료(미종결은 기간 끝까지), 조회 기간 경계에서 자른다
  - 고장이 없으면 1.0이다(관측된 사실이며 꾸민 값이 아니다)
- 시스템 가용도 = 직렬은 곱, 병렬은 1 − (비가용도의 곱)
- 자식 하나라도 산출 불가면 부모도 산출 불가로 하고 원인 설비를 사유로 보인다. 일부 자식만으로 추정하지 않는다
- 설비 하나는 시스템 하나에만 속한다

## 검토한 대안

- **연계를 문서로만 설명**: 작업이 가장 적지만 증명이 없다
- **1단계 고정 구조(직렬 블록 + 병렬 묶음)**: 검증이 거의 필요 없지만 중첩 구조를 표현하지 못한다
- **고유 가용도 MTBF ÷ (MTBF + MTTR)**: 교과서 정의지만 고장 0건·종결 0건이면 산출할 수 없어, 고장 기록이 적은 기간에는 시스템 값이 대부분 산출 불가가 된다
- **구조를 설정 파일에 정의**: 빠르지만 설비 목록이 DB와 설정 두 곳에 있게 되어 서로 어긋나는 새 실패 경로가 생긴다

## 결과와 한계

- 직렬·병렬 공식은 **설비 고장이 서로 독립**이라고 가정한다. 공통 원인 고장(정전 하나로 여러 설비가 정지)은 반영하지 못한다. 개선 경로는 시간 구간별 설비 상태에 구조 함수를 적용하는 계산이다
- 설비마다 관측 시간(공백)이 다른 값을 조합한다
- 구조는 현재 정의 하나만 보관하며, 과거 기간도 현재 구조로 계산한다(구조 변경 이력 없음)
- 범위 밖: k-out-of-n(병렬은 1-out-of-n의 특수 경우라 확장 경로가 열려 있다), 고장 트리 분석(FTA), 실시간 고장 전파, 알람 연쇄 묶기, 제품·로트 단위 공정 추적, 시스템 간 설비 공유
