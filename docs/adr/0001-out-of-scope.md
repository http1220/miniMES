# 0001. 범위 밖 항목과 이유

- 상태: 채택
- 날짜: 2026-09-30 (2026-10-03 개정: 가용도를 범위 안으로 — ADR 0014)

## 맥락

이 프로젝트의 목적은 기능의 폭이 아니라, 실패 상황에서 시스템이 어떻게 동작해야 하는지를 설계로 정하고 테스트로 증명하는 것이다. 정해진 기간 안에 그 증명을 끝내려면 범위를 좁혀야 한다.

## 결정

다음은 만들지 않는다.

| 항목 | 이유 |
|---|---|
| FANUC FOCAS | 전용 라이브러리·라이선스가 필요하고, 증명하려는 실패 처리와 무관하다 |
| OPC UA | 수집 프로토콜을 하나(Modbus TCP)로 좁혀 실패 처리 증명에 집중한다 |
| 카메라·RTSP | 센서 데이터 수집·고장 기록과 무관하다 |
| 자체 DI 컨테이너 | 증명 대상이 아니다. 구성은 진입점에서 직접 조립한다 |
| 배포(설치 프로그램, 서비스 등록) | 증명 대상이 아니다. 각 프로그램은 직접 실행한다 |
| 사이클 카운터(롤오버·리셋) | 센서 데이터를 아날로그 측정값과 설비 상태로 한정했다 |
| 시간별·일별 사전 집계 | 지표 계산에 필요한 만큼만 조회 시 계산한다(ADR 0008) |
| 고장률, MTTF, OEE | 지표는 MTBF·MTTR과 가용도(설비 실적 가용도, 시스템 가용도 — ADR 0014)로 한정했다 |
| 고장 기록 승인 절차, 시정조치 효과 검증 | 고장 기록은 등록·조치·종결까지만 다룬다 |
| 사용자 인증, 역할별 권한 강제 | ADR 0010 |
| 사용자 관리 화면 | 사용자 목록은 SQL 운영 절차로 관리한다 |
| 통신 정상·값 멈춤(stale) 감지 | 판정 규칙이 별도 설계를 요구해 범위를 넘는다 |
| 데이터 자동 삭제 | ADR 0012 |

## 결과

- 수집은 Modbus TCP(Read Holding Registers)만 다룬다
- 위 항목이 필요해지면 새 ADR로 범위를 다시 정한다
